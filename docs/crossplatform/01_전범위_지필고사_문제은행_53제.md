### 문제 2. [유형 2: 동작 원리 & 개념 서술형] (배점: 10점)
* **문제:** 3주차 교안에 등장하는 리액트 네이티브 컴포넌트 정렬 3대 속성인 `flexDirection`, `justifyContent`, `alignItems`에 대해 다음 물음에 답하시오.
  1. `flexDirection`의 기본값(Default)을 쓰고, 컴포넌트가 배치되는 방향을 설명하시오.
  2. `justifyContent`의 `space-between`, `space-around`, `space-evenly`의 배치 차이점을 서술하시오.
  3. `alignItems`의 `stretch`와 `baseline` 속성값의 동작 원리를 서술하시오.
* **제시 코드:** 없음 (교안 5~7페이지 핵심 이론)
* **[정답 및 모범 답안]**
  1. `flexDirection`의 기본값은 `column`이며, 컴포넌트를 세로 방향으로 위에서 아래로 정렬한다.
  2. 
     - `space-between`: 컴포넌트 '사이'의 공간을 동일하게 배분하여 정렬한다.

  3. 
     - `stretch`: `alignItems`의 방향으로 컴포넌트를 끝까지 확장시킨다.
     - `baseline`: 컴포넌트 내부의 텍스트(Text) 베이스라인(Baseline)을 기준으로 정렬한다.
* **[해설 및 채점 기준]**

### 문제 5. [유형 2: 동작 원리 & 개념 서술형] (배점: 10점)
* **문제:** 아래의 인라인 스타일링 코드에서 `fontWeight` 속성에 값을 지정할 때 교안에서 특별히 주석으로 강조한 주의사항이 무엇인지 쓰고, 일반 웹 표준 CSS와 어떤 차이가 있는지 서술하시오.
* **제시 코드:**
```javascript
export default function App() {
  return (
    <View
      style={{
        flex: 1,
        backgroundColor: "#fff",
        alignItems: "center",
        justifyContent: "center",
      }}>
      <Text
        style={{
          padding: 10,
          fontSize: 26,
          fontWeight: "600", // 주석: 숫자가 아닌 문자열
          color: "black",
        }}>
        Inline Styling - Text
      </Text>
      <Text
        style={{
          padding: 10,
          fontSize: 26,
          fontWeight: "400", // 주석: 숫자가 아닌 문자열
          color: "red",
        }}>
        Inline Styling - Error
      </Text>
    </View>
  );
}
```
* **[정답 및 모범 답안]**
  - **주의사항:** 리액트 네이티브에서 `fontWeight` 속성값은 숫자가 아닌 **반드시 문자열(String, 예: `"600"`, `"400"`)**로 감싸서 지정해야 한다.

* **[해설 및 채점 기준]**
  - '숫자가 아닌 문자열'이라는 점을 명확히 명시해야 정답 인정 (교안 11페이지).

### 문제 7. [유형 3: 코드 실행 결과 / 값 도출형] (배점: 10점)
* **문제:** 아래 코드에서 두 번째 `<Text>` 컴포넌트에는 `style={[styles.text, styles.error]}`와 같이 배열 형태로 스타일이 적용되어 있다. 최종적으로 렌더링되는 두 번째 텍스트의 글자 색상(`color`), 글자 두께(`fontWeight`), 안쪽 여백(`padding`), 글자 크기(`fontSize`)를 각각 쓰고, 왜 그러한 스타일이 적용되는지 원리를 서술하시오.
* **제시 코드:**
```javascript
export default function App() {
  return (
    <View style={styles.container}>
      <Text style={styles.text}>Inline Styling - Text</Text>
      <Text style={[styles.text, styles.error]}>Inline Styling - Error</Text>
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    backgroundColor: '#fff',
    alignItems: 'center',
    justifyContent: 'center',
  },
  text: {
    padding: 10,
    fontSize: 26,
    fontWeight: '600',
    color: 'black',
  },
  error: {
    fontWeight: '400',
    color: 'red',
  },
});
```
* **[정답 및 모범 답안]**
  - **최종 적용 스타일:**
    - `padding`: `10`
    - `fontSize`: `26`
    - `fontWeight`: `'400'`
    - `color`: `'red'`
  - **원리 설명:** 리액트 네이티브에서 배열(`[]`)을 통해 여러 개의 스타일을 적용할 경우, 배열의 뒤쪽에 위치한 스타일 객체(`styles.error`)가 앞쪽 스타일 객체(`styles.text`)의 중복 속성(`fontWeight`, `color`)을 덮어쓰고(Override), 중복되지 않는 속성(`padding`, `fontSize`)은 그대로 상속·합성된다.
* **[해설 및 채점 기준]**
  - 교안 13페이지 예제 기반. 배열 후순위 스타일 우선 적용 원리를 명확히 서술해야 함.

  2. **동작 원리:** 의존성 배열의 값이 바뀌지 않은 상태에서 컴포넌트가 리렌더링될 경우, 콜백 함수 내부의 계산식을 다시 실행하지 않고 **기존에 메모이제이션(기억)해 둔 결과값(`memoizedValue`)을 그대로 반환**한다.
* **[해설 및 채점 기준]**
  - 교안 16페이지에 근거한 불필요한 재계산 방지, 성능 최적화, 메모이제이션 개념 기술 여부 평가.

### 문제 53. [유형 3: 코드 실행 결과 / 값 도출형] (배점: 10점)
* **문제:** 아래의 `App` 컴포넌트에서 `double` 값은 `useMemo`로 `[count]`에 의존하고 있다. 컴포넌트 최초 렌더링이 완료된 후, 사용자가 다음 순서로 버튼을 조작하였다.
  * **[사용자 동작]**
    1. `"텍스트 변경"` 버튼을 1번 클릭함.
    2. `"카운트 +1"` 버튼을 1번 클릭함.
  * **[질문]**
    (1) 1번 동작(`"텍스트 변경"` 클릭) 시 콘솔에 `"double 계산 실행!"`이 출력되는지 여부와 화면의 `Count`, `Double`, `Character` 텍스트 출력값을 적으시오.
    (2) 2번 동작(`"카운트 +1"` 클릭) 시 콘솔에 `"double 계산 실행!"`이 출력되는지 여부와 화면의 `Count`, `Double`, `Character` 텍스트 출력값을 적으시오.
* **제시 코드:**
```javascript
import React, { useState, useMemo } from "react";
import { StyleSheet, View, Text, Button } from "react-native";

export default function App() {
  const [count, setCount] = useState(0);
  const [text, setText] = useState("");

  const double = useMemo(() => {
    console.log("double 계산 실행!");
    return count * 2;
  }, [count]);

  return (
    <View style={styles.container}>
      <Text style={styles.text}>Count: {count}</Text>
      <Text style={styles.text}>Double: {double}</Text>
      <Button title="카운트 +1" onPress={() => setCount(count + 1)} />
      <Button title="텍스트 변경" onPress={() => setText(text + '강남대 ')} />
      <Text style={styles.text}>Character: {text}</Text>
    </View>
  );
}
```
* **[정답 및 모범 답안]**
  (1) **1번 동작 (`"텍스트 변경"` 클릭 시):**
  - 콘솔 출력 여부: **출력되지 않음 (미실행)**
  - `Count`: `0`
  - `Double`: `0`
  - `Character`: `강남대 `
  - **이유:** `text` 상태가 바뀌어 화면이 리렌더링되었으나, `double`의 의존성인 `count`는 변하지 않았으므로 `useMemo` 내부 연산이 실행되지 않고 이전 결과값 0을 재사용함.

  (2) **2번 동작 (`"카운트 +1"` 클릭 시):**
  - 콘솔 출력 여부: **`double 계산 실행!` 출력됨**
  - `Count`: `1`
  - `Double`: `2`
  - `Character`: `강남대 `
  - **이유:** `count` 상태가 0에서 1로 변경되었으므로 `useMemo`가 의존성 변경을 감지하고 콜백 함수를 다시 실행하여 콘솔을 출력하고 `1 * 2 = 2`를 반환함.
* **[해설 및 채점 기준]**
  - 교안 17~18페이지의 useMemo 최적화 동작을 완벽히 이해하고 있는지 평가하는 핵심 문항.
