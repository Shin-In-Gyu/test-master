## 📊 Part 1. [공식 & 계산 킬러 3대장] 시험지 받자마자 여백에 적어야 할 핵심 공식

### 1. 스케줄링 시간 계산 공식 (가장 기본이자 실수 1순위)
* **대기 시간 (Waiting Time)**: 프로세스가 준비 큐(Ready Queue)에서 대기한 순수 시간
  $$\text{대기 시간} = \text{반환 시간} - \text{CPU 버스트 시간} = (\text{종료 시각} - \text{도착 시각}) - \text{CPU 버스트 시간}$$
  *(단, 비선점형이고 도착 시각이 0이면 $\text{대기 시간} = \text{시작 시각}$)*
* **반환 시간 (Turnaround Time)**: 도착한 시각부터 작업을 완전히 마칠 때까지 걸린 총 시간
  $$\text{반환 시간} = \text{종료 시각} - \text{도착 시각} = \text{대기 시간} + \text{CPU 버스트 시간}$$
* **응답 시간 (Response Time)**: 작업이 도착한 후 CPU를 처음으로 할당받기까지 걸린 시간
  $$\text{응답 시간} = \text{첫 실행 시작 시각} - \text{도착 시각}$$

---

### 2. 다음 CPU 버스트 시간 예측 공식 (지수 이동평균, Exponential Smoothing)
$$\tau_{n+1} = \alpha t_n + (1 - \alpha) \tau_n$$
* $t_n$: 최근 $n$번째 **실제 측정된** CPU 버스트 시간
* $\tau_n$: $n$번째 **예측되었던** CPU 버스트 시간
* $\alpha$: 가중치 ($0 \le \alpha \le 1$, 보통 문제에서 $\alpha = 0.5$ 제시)
* **초스피드 암기**: "새 예측치 = (가중치 × 방금 실제값) + ((1 - 가중치) × 직전 예측치)"

---

### 3. 환형 버퍼 (Circular Buffer) 생산자-소비자 판별식 (크기 $N$)
* **비어 있는(Empty) 조건**: `in == out`
* **가득 찬(Full) 조건**: `(in + 1) % N == out` (크기 $N$일 때 $N-1$개 차면 Full로 판정하여 Empty와 구분)
* **포인터 갱신**: `in = (in + 1) % N;` (생산자), `out = (out + 1) % N;` (소비자)

---

### 4. 연쇄 `fork()` 생성 프로세스 개수 공식
* `fork()`를 연속 $n$번 호출 시:
  * **총 생성된 프로세스 수 (부모 포함)**: $2^n$개
  * **새로 생성된 자식 프로세스 수**: $2^n - 1$개
  * 루프 `for(i=0; i<n; i++) fork();` 뒤의 `printf` 출력 횟수: $2^n$번

## 💻 Part 2. [교수님 육성 박제] 시험 출제 100% 확정 코드 & 서술형 킬러

### 🔴 킬러 1. `fork()` 후 자식이 전역 변수를 수정할 때 부모의 값 (출제율 100%)
* **문제 유형**: 자식이 `value += 15;`를 했을 때 부모가 출력하는 `value` 값은?
* **핵심 정답**: **부모의 본래 값 그대로 유지됨! (예: `value = 5` 그대로 출력)**
* **서술형 근거 (반드시 적어야 할 키워드)**:
  1. `fork()` 시 자식 프로세스는 부모의 주소 공간(Text, Data, Heap, Stack)을 복사하여 **독립적인 별도의 메모리 공간**을 갖는다 (Copy-on-Write 메커니즘).
  2. 자식 프로세스가 전역 변수를 수정하더라도 **자식 프로세스의 데이터 영역만 수정**되며, 부모 프로세스의 메모리 영역에는 전혀 영향을 미치지 않는다.

---

### 🔴 킬러 2. `fork()` 반환값 `pid` 변수 vs `getpid()`의 차이
* **`fork()`의 반환값**:
  * **부모 프로세스에게 반환**: 새로 생성된 **자식 프로세스의 PID (0보다 큰 양의 정수)**
  * **자식 프로세스에게 반환**: 숫자 **`0`**
  * **실패 시**: `-1`
* **`getpid()`**: 시스템 콜을 호출한 **자기 자신의 실제 고유 PID** 반환
* **코드 출력 함정**:
  ```c
  pid = fork();
  if (pid == 0) { // 자식
      printf("%d %d", pid, getpid()); // 출력: 0 [자식 본인 실제PID]
  } else {        // 부모
      wait(NULL);
      printf("%d %d", pid, getpid()); // 출력: [자식 실제PID] [부모 본인 실제PID]
  }
  ```

---

### 🔴 킬러 3. `execlp()` 실행 후 뒤에 오는 코드의 실행 여부
* **코드 예시**:
  ```c
  if (pid == 0) {
      execlp("/bin/ls", "ls", NULL);
      printf("THIS LINE WILL NEVER RUN\n"); // 실행되는가?
  }
  ```
* **정답**: 뒤따라오는 `printf`는 **절대로 실행되지 않는다**.
* **이유**: `exec` 계열 시스템 콜은 현재 프로세스의 주소 공간(코드, 데이터, 힙, 스택)을 **새로운 실행 파일의 내용으로 완전히 덮어쓰기(Replace)**하기 때문이다. 기존 코드는 메모리에서 증발하고 새 프로그램의 `main()`부터 실행된다.

---

### 🔴 킬러 4. 스레드(Thread) vs 프로세스 메모리 구조 (도식화 & 서술 단골)
* **교수님 녹음 강조**: *"머릿속에 박혀 있어야 돼! 직접 그려보라고 낼 수 있어!"*
* **동일 프로세스 내 스레드들이 공유하는 자원 (4가지)**:
  1. **코드 영역 (Code / Text)**
  2. **데이터 영역 (Data)**: 전역 변수, 정적(static) 변수
  3. **힙 영역 (Heap)**: 동적 메모리(`malloc`)
  4. **운영체제 자원**: 열린 파일(Open Files), I/O 장치
* **각 스레드가 독립적으로 소유하는 전용 자원 (4가지)**:
  1. **스레드 ID (TID)**
  2. **프로그램 카운터 (PC)**: 각 스레드가 실행 중인 다음 명령어 주소
  3. **레지스터 집합 (Register Set)**: CPU 상태 레지스터 값
  4. **스택 영역 (Stack)**: 독립적인 함수 호출 프레임, 지역 변수, 반환 주소
* ⚠️ **스레드와 전역 변수**: 프로세스와 달리 스레드는 데이터 영역을 공유하므로, **스레드 A가 전역 변수를 수정하면 스레드 B와 메인 스레드에도 즉시 반영된다!**

---

### 🔴 킬러 5. `wait()`의 유무에 따른 프로세스 상태: 좀비 vs 고아
| 구분 | 발생 원인 | 해결 / 수습 방법 | 상태 표기 |
| :--- | :--- | :--- | :--- |
| **좀비 프로세스 (Zombie)** | 자식이 종료되었는데, **부모가 `wait()`를 호출하지 않아** 종료 상태 및 PCB가 메모리에 방치된 상태 | 부모가 `wait()`를 호출하면 완전히 제거됨 | `<defunct>` |
| **고아 프로세스 (Orphan)** | 부모 프로세스가 자식보다 **먼저 종료**되어 부모를 잃어버린 자식 프로세스 | OS의 루트 프로세스(**`init` / `systemd`, PID 1**)가 양부모로 입양하여 종료 시 `wait()` 대리 회수 | 정상 동작 후 회수 |

## 📈 Part 3. [간트 차트 30초 컷] 스케줄링 4대 알고리즘 핵심 족보

### 1. FCFS (First-Come, First-Served, 선입선출)
* **방식**: 비선점형(Non-preemptive). 먼저 도착한 순서대로 CPU 끝까지 할당.
* **단점 / 킬러 용어**: **콘보이 효과 (Convoy Effect / 호소 효과)**
  * 버스트 시간이 긴 프로세스가 먼저 CPU를 독점하면 짧은 프로세스들이 뒤에서 장시간 대기하여 시스템 전체의 평균 대기시간이 극도로 증가하는 현상.

---

### 2. SJF (Shortest Job First) — 비선점형
* **방식**: 준비 큐에 있는 프로세스 중 **CPU 버스트 시간이 가장 짧은 것**부터 실행. (중간에 뺏지 않음!)
* **장점**: 주어진 프로세스 집합에 대해 **최소의 평균 대기 시간(Optimal Minimum Average Waiting Time)**을 보장.
* **단점**:
  1. 실제 시스템에서는 다음 CPU 버스트 시간을 미리 알 수 없음 (지수 이동평균으로 예측만 가능).
  2. **기아 현상(Starvation)** 발생 가능: 긴 프로세스는 영원히 실행되지 못함.
  3. 해결책: **에이징 (Aging)** — 대기 시간이 길어질수록 우선순위를 점진적으로 증가시킴.

---

### 3. SRTF (Shortest Remaining Time First) — 선점형 SJF (★최다 빈출 계산)
* **방식**: 새로운 프로세스가 도착할 때마다 **"남아있는 버스트 시간(Remaining Time)"**을 비교하여, 실행 중인 것보다 짧으면 즉시 CPU를 빼앗아 할당함(Preemption).
* **실전 풀이 3단계 요령**:
  1. **사건 발생 시점(새 프로세스 도착 시점)**마다 CPU를 멈추고 표를 업데이트한다.
  2. 현재 남은 시간: `(기존 작업 남은 시간) vs (새로 도착한 작업 버스트 시간)` 비교.
  3. 같으면 기존 작업 계속, 새 작업이 더 작으면 **즉시 선점(스위칭)**!

---

### 4. Round Robin (RR, 라운드 로빈) — (중간고사 마지막 범위)
* **방식**: 선점형(Preemptive). 각 프로세스에 동일한 **시간 할당량 (Time Quantum, $q$)**을 부여하고 순환하며 실행.
* **할당량 초과 시**: 타이머 인터럽트 발생 $\rightarrow$ 프로세스는 준비 큐 맨 뒤(Tail)로 이동.
* **시간 할당량 $q$ 크기가 미치는 영향 (서술형 단골!)**:
  * **$q \rightarrow \infty$ (너무 클 때)**: 프로세스가 한 번에 끝나므로 **FCFS와 완전히 동일해짐**.
  * **$q \rightarrow 0$ (너무 작을 때)**: CPU 스위칭이 너무 빈번해져 **문맥 교환(Context Switching) 오버헤드(디스패치 지연)**가 극심해져 시스템이 마비됨.
  * **권장 기준**: 전체 CPU 버스트의 약 **80%는 단일 시간 할당량 내에 완료**되도록 $q$를 설정.

## 📚 Part 4. [1장~6장] 적어도 이 용어 모르면 들어가지 마라 (단답형 핵심)

### 📌 1장: 컴퓨터 시스템 개요 & 운영체제 구조
* **운영체제의 2대 목적**: 사용자 편의성 (User Convenience), 자원 효율성 (Resource Efficiency)
* **폰 노이만 구조**: 프로그램과 데이터가 동일한 메인 메모리에 저장되어 순차 실행되는 **내장 프로그램(Stored-program) 방식**.
* **이중 모드 (Dual-Mode Operation)**:
  * **사용자 모드 (User Mode, Mode bit = 1)**: 제한된 명령어만 실행 가능. 하드웨어 직접 접근 불가.
  * **커널 모드 (Kernel / Monitor / Privileged Mode, Mode bit = 0)**: 모든 기계어 및 하드웨어 제어 가능.
  * **특권 명령 (Privileged Instruction)**: 커널 모드에서만 실행 가능한 위험 명령어 (I/O 제어, 타이머 설정, 모드 비트 변경, 인터럽트 금지 등).
* **하드웨어 타이머 (Timer)**: 무한 루프나 특정 프로그램의 CPU 독점을 방지하기 위해 일정 주기마다 OS에 인터럽트를 걸어 CPU 제어권을 회수하는 필수 장치.
* **인터럽트(Interrupt) vs 트랩(Trap)**:
  * **하드웨어 인터럽트**: 외부 I/O 장치나 타이머가 CPU 핀에 전기 신호를 보내 발생.
  * **트랩 / 익셉션 (Software Interrupt)**: 실행 중인 프로그램 내부 오류(0으로 나누기, 잘못된 메모리 접근) 또는 **시스템 콜(System Call)** 호출 시 발생.

---

### 📌 2장: 프로세스 (Process) & 문맥 교환
* **프로세스 5가지 상태 전이도**:
  * `New` $\rightarrow$ `Ready` (준비 큐 진입)
  * `Ready` $\rightarrow$ `Running` (스케줄러의 **디스패치**)
  * `Running` $\rightarrow$ `Waiting / Blocked` (I/O 요청 또는 이벤트 대기)
  * `Waiting` $\rightarrow$ `Ready` (I/O 완료 인터럽트 발생 시)
  * `Running` $\rightarrow$ `Ready` (**타이머 인터럽트 만료(Timeout)** 또는 선점)
  * `Running` $\rightarrow$ `Terminated` (실행 완료)
* **PCB (Process Control Block)**: OS가 프로세스를 제어하기 위한 모든 정보를 담은 자료구조 (PID, 프로세스 상태, PC, CPU 레지스터, 메모리 관리 정보, 열린 파일 목록).
* **문맥 교환 (Context Switch)**: CPU 제어권을 한 프로세스에서 다른 프로세스로 넘길 때, 이전 프로세스의 상태(문맥)를 PCB에 저장하고 새 프로세스의 PCB로부터 복원하는 작업. 순수한 계산 작업이 아니므로 **시스템 오버헤드(Overhead, 순수 낭비 시간)**에 해당.
* **디스패처 (Dispatcher)**: CPU 스케줄러에 의해 선택된 프로세스에게 실질적으로 CPU 제어권을 넘겨주는 모듈 (문맥 교환 수행, 사용자 모드 전환, 프로그램 재개 점프).
* **디스패치 지연 (Dispatch Latency)**: 디스패처가 한 프로세스를 중지하고 다음 프로세스를 시작할 때까지 걸리는 총 소요 시간.

### 📌 3~4장: 프로세스 간 통신 (IPC)
* **IPC 2대 메커니즘 비교**:
  | 비교 항목 | 공유 메모리 (Shared Memory) | 메시지 전달 (Message Passing) |
  | :--- | :--- | :--- |
  | **통신 속도** | **매우 빠름** (초기 구축 후 커널 개입 없음) | **상대적으로 느림** (송수신마다 시스템 콜/커널 버퍼 복사 발생) |
  | **동기화 책임** | **응용 프로그래머가 직접 동기화 구현** | **커널이 자체 큐와 동기화 기능 제공** |
  | **적합 환경** | 동일 머신 내 대용량 데이터 고속 전송 | 분산 네트워크 시스템 또는 소량 메시지 교환 |
* **파이프 (Pipe)**:
  * **일반 파이프 (Ordinary Pipe)**: 단방향(Half-duplex) 통신, 부모-자식 간에만 사용 가능, 프로세스 종료 시 자동 소멸.
  * `fd[0]`: 읽기 전용(Read-end), `fd[1]`: 쓰기 전용(Write-end)
* **블로킹(동기) vs 논블로킹(비동기)**:
  * Blocking Send: 수신자가 받을 때까지 송신자가 멈춤.
  * Non-blocking Send: 큐에 넣고 즉시 복귀.

### 📌 5~6장: 멀티스레드 모델 & 병렬 처리
* **동시성(Concurrency) vs 병렬성(Parallelism)**:
  * **동시성**: 단일 코어에서 여러 작업이 시분할 인터리빙으로 번갈아 실행되어 동시에 실행되는 것처럼 보이는 것.
  * **병렬성**: 멀티 코어에서 실제로 물리적으로 여러 작업이 동시에 실행되는 것.
* **멀티스레드 3대 모델**:
  1. **다대일 (Many-to-One)**: 사용자 스레드 여러 개가 커널 스레드 1개에 매핑. 한 스레드가 블록되면 전체 프로세스가 멈춤, 멀티코어 병렬 실행 불가.
  2. **일대일 (One-to-One)**: 사용자 스레드 1개당 커널 스레드 1개 (Linux, Windows). 병렬 실행 가능하나 스레드 생성 비용/오버헤드 큼.
  3. **다대다 (Many-to-Many)**: 사용자 스레드 $M$개를 $N$개의 커널 스레드로 융통성 있게 매핑 ($M \ge N$).
* **OpenMP 지시어**: `#pragma omp parallel` (컴파일 시 `gcc -fopenmp` 옵션 필수).

## 🎯 Part 5. [자가 채점 3분 완성] 시험 직전 5대 최종 점검 문답

1. **Q. `fork()` 후 자식에서 전역 변수를 바꾸면 부모는 어떻게 되는가?**
   * **A.** 부모 변수는 바뀌지 않고 원본 유지. (서로 독립된 메모리 주소 공간을 가짐)
2. **Q. 계산 문제에서 간트 차트를 안 그리면 어떻게 되는가?**
   * **A.** 답이 맞아도 50% 즉시 감점! 시간 눈금(0, 1, 5, 10...)을 무조건 그린다.
3. **Q. SJF가 최적(Optimal) 알고리즘인 이유는?**
   * **A.** 주어진 프로세스 집합에 대해 "평균 대기 시간(Average Waiting Time)"을 최소화하기 때문.
4. **Q. FCFS에서 발생하는 콘보이 효과의 원인과 결과는?**
   * **A.** CPU 버스트가 긴 작업이 앞서 독점하여 뒤의 짧은 작업들이 장시간 대기하게 되고, 평균 대기시간이 급증하여 장치 이용률이 떨어짐.
5. **Q. 라운드 로빈에서 시간 할당량 $q$가 너무 클 때와 너무 작을 때의 문제는?**
   * **A.** 너무 크면 FCFS와 동일해지고, 너무 작으면 잦은 문맥 교환으로 인한 디스패치 오버헤드가 극심해짐.
